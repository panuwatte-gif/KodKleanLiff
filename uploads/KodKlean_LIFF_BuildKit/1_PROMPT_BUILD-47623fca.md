## เงื่อนไขบังคับ (กติกาที่ห้ามผิด)
═══════════════════════════════════════════
1. **สมองเดียวหลายประตู:** business logic ทั้งหมด (คัดกรอง, จับคู่, ลงบัญชี, สร้างเอกสาร, จัดการไฟล์) อยู่ใน Supabase Edge Functions — หน้าจอเป็นเปลือกเรียก API เท่านั้น ห้ามมี logic ในหน้าจอ (ภายหลังมี webapp มาต่อสมองเดิม)
2. **Vanilla JS + ES Modules แยกไฟล์** ไม่ใช้ framework/build tool — เจ้าของแก้เองไม่ได้ ต้องให้ AI มาแก้ต่อง่าย ทุกไฟล์คอมเมนต์หัวว่าทำอะไร/แก้เรื่องนี้มาที่นี่
3. **Never block ตอนเก็บ/ร่าง** (ข้อมูลไม่ครบก็บันทึกร่างได้ + mark ว่าขาดอะไร) — **block เฉพาะตอนยืนยัน/เซ็นเอกสารที่ต้องมีฟิลด์บังคับครบ**
4. **แก้ไขได้เสมอ ไม่ลบของเดิม:** ยังไม่ลงบัญชี=แก้ทับ+เก็บประวัติ / ลงบัญชีแล้ว=สร้างรายการกลับ(reversal) / เอกสารเซ็นแล้ว=ออกใบใหม่แทน ใบเก่า void — ห้าม DELETE ข้อมูลเงินจริง
5. **ตัวเลขทุกจุดคำนวณจริงจากฐานข้อมูล** ห้าม hardcode
6. **ผู้ใช้ Android 100%:** optimize Chrome Android + เบราว์เซอร์ใน LINE, กล้อง input capture, lazy-load, ฟอนต์ Noto Sans Thai — ไม่ต้องทำ workaround iOS
7. **ขอบเขต Phase 1:** ทำฝั่งซื้อ+เงินออก / ยังไม่ทำ ค่าเสื่อม·ปิดงบ·งบดุลเต็ม·ยื่นภาษี **แต่เก็บข้อมูลดิบครบทุกอย่าง** (flag ของถาวร, journal คู่, VAT, book_scope) เพื่อเปิดฟีเจอร์ทีหลังไม่ต้องรื้อ
8. **รหัส route (1a/1b/2a/2b) ใช้ในฐานข้อมูลเท่านั้น** หน้าจอแสดงข้อความเต็มเสมอ ห้ามโชว์รหัสให้ผู้ใช้

## UI (กำหนดแค่นี้ ที่เหลืออิสระ)
Mobile-first 390px, ปุ่ม≥48px, ฟอนต์≥16px / แนวการ์ดกดง่ายแบบแอปสั่งอาหาร ไม่ใช่ตาราง Excel / ใช้ asset รูปที่ให้มา (ตัวการ์ตูนอาเฮีย-แม่พันจับคู่วัยเดียวกัน, มาสคอต, โลโก้, รูปสินค้า) ไม่สร้างรูปเอง / ทุกหน้ามี loading + empty + error ภาษาไทย

## กระบวนการทำงาน (ละเอียด)
═══════════════════════════════════════════

### ▶ กระบวนการ A: บันทึกการซื้อ (เส้นทางหลัก)
จุดเริ่มได้หลายทาง (never block — หลักฐานชิ้นไหนมาก่อนเริ่มจากชิ้นนั้น):

**A1. เลือกร้าน** → แสดงร้านจากฐานข้อมูล (ซื้อบ่อยขึ้นก่อน) + ค้นหา + ปุ่มเพิ่มร้านใหม่ (กรอกสั้นๆใช้ได้ทันที)

**A2. เลือกสินค้า + จำนวน** → ดึง vendor_items ของร้านนั้นมาแสดง (ชื่อ, สเปคจริงเช่น "16/20 · NW80%", หน่วยขายจริงเช่นแพ็ก/กก., ราคาล่าสุด, รูป)
- ปรับจำนวน → คำนวณยอดต่อรายการสดๆ → รวมยอดทั้งบิลสด
- แก้ราคา → ระบบถาม "บันทึกเป็นราคาใหม่ของร้านนี้ไหม?" ตอบใช่=เก็บลง price history
- สินค้าใหม่ยังไม่มี → ปุ่มเพิ่มด่วน

**A3. ค่าส่ง + ค่าลังโฟม** → เด้งจากค่า default ของร้าน (แก้ได้ทุกครั้ง เพราะร้านแชทไม่เท่ากันแต่ละรอบ)

**A4. คัดกรองเอกสาร** → ถาม "เอกสารจากผู้ขายเป็นแบบไหน?" 4 ทาง (ข้อความเต็ม):
- "มีใบกำกับภาษี (มี VAT)" → route 1a: ไม่สร้างเอกสารเพิ่ม + แยกภาษีซื้อเก็บ (ใช้งบจำลอง)
- "มีบิล/ใบเสร็จ (ไม่มี VAT)" → route 1b: ไม่สร้างเอกสารเพิ่ม
- "มีแค่สลิปโอน" (พบบ่อยสุด) → route 2a: สร้างใบสำคัญจ่าย + แนบสลิป
- "ไม่มีเอกสารเลย" → route 2b: ถามต่อวิธีจ่าย
  - โอน(มีสลิป พิสูจน์ผู้รับได้) → ใบสำคัญจ่าย → ลงภาษีได้
  - จ่ายสด ไม่มีตัวผู้รับให้พิสูจน์(แท็กซี่/วิน) → ใบรับรองแทนใบเสร็จ → ลงภาษีได้
  - จ่ายสด พิสูจน์ผู้รับไม่ได้เลย → tag inhouse_only → เข้าเฉพาะงบส่วนตัว ห้ามเข้างบจำลองนิติ (ระบบกันอัตโนมัติ)
- AI ช่วยอ่านรูปแล้วติ๊กทางที่น่าจะใช่ให้ก่อน ผู้ใช้ยืนยัน/เปลี่ยน / ถ้าเลือก 2b+เงินสด เตือนนุ่มๆ "โอนได้แนะนำโอน จะลงภาษีได้"

**A5. แนบหลักฐาน (เช็คลิสต์เอกสารตามร้าน)** → แสดงช่องเอกสารที่ร้านนี้ต้องมี (จาก doc_checklist) เป็นช่องถ่าย/เลือกไฟล์ มีแล้วติ๊ก
- ครบ → ปุ่ม "ส่งเข้าระบบ" ทำงาน
- ไม่ครบ → ปุ่ม "บันทึกร่าง" → ไปตะกร้ารอจับคู่ เติมทีหลังได้

**A6. สรุป → ยืนยัน** → แสดงเส้นทาง/หมวด/ที่เก็บ/เข้างบไหน (ทุกช่องแก้ได้) → ยืนยัน → เข้ากระบวนการ C (ลงบัญชี+เอกสาร+เก็บไฟล์)

*ทางเลือก AI ช่วยกรอก:* บิลยาว(Makro หลายรายการ) กดปุ่ม "ให้ AI อ่านจากรูป" → AI vision เติมฟอร์มให้ → คนตรวจ/แก้ → เข้า A4 ปกติ
*ทางลัดค่าใช้จ่ายไม่ใช่สินค้า* (ค่าไฟ/เช่า/เบ็ดเตล็ด): ฟอร์มแยก ไม่ต้องเลือกสินค้า
*ของถาวร (ตู้เย็น):* ถามใช่/ไม่ใช่ → Phase 1 แค่บันทึก flag ลง assets ลงค่าใช้จ่ายทันที ไม่คำนวณค่าเสื่อม

### ▶ กระบวนการ B: จับคู่ + รับของ
- **สลิปเดียวหลายร้าน:** หัวจ่าย 1 + แตกบรรทัดรายร้าน แต่ละบรรทัดเลือกร้าน+หมวด+ยอด ผลรวมต้อง=ยอดสลิป ถึงยืนยันได้ → แต่ละบรรทัดเดินเข้า route ของตัวเอง
- **ตะกร้ารอจับคู่:** ร่างที่หลักฐานไม่ครบมารออยู่ที่นี่ แสดง checklist มี/ขาด เติมชิ้นที่ขาดได้ ครบแล้วปุ่มสร้างเอกสารทำงาน
- **รับของ:** แสดงรายการที่สั่งเป็นแถวเรียบ (ชื่อ | สั่งกี่หน่วย | ช่องกรอก"รับจริง" default=จำนวนสั่ง หน่วยตาม sell_unit จริง) — รับครบไม่ต้องแตะ / ถ่ายรูปของที่มาส่งจริง + ป้ายค้างกี่วัน
- **ของขาด:** ระบุจำนวนขาด → คิดเป็นเงิน(จำนวนขาด×ราคาต่อหน่วย) → เลือก: ร้านส่งเติม(รอของมา convert เป็นสินค้า) / ร้านคืนเงิน(รอเงินเข้า match ปิดยอด) / ลง loss → เปิดเคสติดตามจนปิด

### ▶ กระบวนการ C: ลงบัญชี + สร้างเอกสาร (หลังบ้าน ผู้ใช้ไม่เห็น)
เมื่อยืนยันรายการ ระบบทำอัตโนมัติ:
1. **ลงบัญชีคู่** (เดบิต=เครดิต บาลานซ์) ตามประเภทรายการ — ทุก journal_line ติด book_scope:
   - `both` = เข้าทั้ง 2 งบ (รายการเอกสารครบ)
   - `inhouse_only` = เข้าเฉพาะงบส่วนตัว
   - รายการ 1a → เพิ่ม vat_line (ภาษีซื้อ)
2. **สร้างเอกสาร** ตาม route (ใบสำคัญจ่าย/ใบรับรอง) — ฟิลด์ตามคู่มือกรมสรรพากรครบ: ชื่อ-ที่อยู่-เลขภาษี/บัตรผู้รับ, วันที่, รายการ+เงิน, จำนวนเงินตัวอักษรไทย, ช่องลายเซ็นผู้รับ+ผู้อนุมัติ, แนบหลักฐานจ่าย → สถานะ draft
3. **มัดเป็น 1 CASE** รวมเอกสาร+หลักฐานทั้งชุด

### ▶ กระบวนการ D: อนุมัติ + ลายเซ็น (เฉพาะ owner)
- แสดงเอกสาร draft จัดกลุ่มตามกิจการ → เลือกหลายใบ batch approve
- ลายเซ็นแปะ **เมื่อกดยืนยันเท่านั้น** (ไม่ใช่แปะอัตโนมัติ) + บันทึก log (ใคร/เวลา/hash เอกสาร) — นี่คือเจตนาทางกฎหมาย
- ก่อนเซ็น ถ้าฟิลด์บังคับยังขาด → บอกชัดว่าขาดช่องไหน กดเซ็นไม่ได้จนเติม

### ▶ กระบวนการ E: จัดเก็บไฟล์
- **หลักฐานภาษี (บิล/สลิป/เอกสาร):** ต้นฉบับย่อ 2560px JPEG q85 → Google Drive โฟลเดอร์ `กิจการ/ปี/เดือน/CASE-เลขที่/` (1 CASE=1 โฟลเดอร์) เก็บ ≥5 ปี / thumbnail WebP → Supabase (ไว้แสดงในแอป) / sha256 กันไฟล์ซ้ำ / Drive ล่ม=พัก pending คิว retry ลบทันทีที่ sync สำเร็จ — **ห้ามเก็บต้นฉบับถาวรใน Supabase**
- **รูป master data (สินค้า/โลโก้):** ไม่ใช่หลักฐานภาษี → บีบ+แปลง WebP อัตโนมัติฝั่ง client ก่อนอัปโหลด → เก็บ Supabase ได้เลย

### ▶ กระบวนการ F: งบ 2 ชุด (จาก journal ชุดเดียว ต่างที่ filter)
- **งบส่วนตัว (ดูเอง):** รวม journal_line ทุกอันไม่สนเอกสาร → P&L(กำไรจริง) + Cashflow(เงินเข้า-ออกจริง)
- **งบจำลองถ้าจดนิติ:** กรองเฉพาะ book_scope=both → P&L แบบนิติ + ตาราง VAT(ภาษีซื้อ−ขาย=ต้องจ่าย/ขอคืน)
  - **ยังไม่สมบูรณ์โดยตั้งใจ:** ต้นทุนขายจริงรอเชื่อม App_stock (เฟสนี้ยังไม่ต่อ) → เห็นแค่ค่าใช้จ่ายฝั่งซื้อ + เงินไหลออก → **แสดงหมายเหตุ "ต้นทุนขายจริงรอเชื่อม App_stock"**
- ยอดย่อย (เอกสารครบ + ไม่ครบ) รวมกันต้อง = ยอดรวมเสมอ

### ▶ กระบวนการ G: Dashboard (ฝั่งซื้อ+เงินออกเท่านั้น)
- การ์ด: เงินไหลออกเดือนนี้(ตัวใหญ่) + งานค้าง(รออนุมัติ/ค้างรับ/ของขาด กดดูรายการได้)
- กราฟ: ค่าใช้จ่าย 12 เดือน(เดือนนี้สีเด่น) · VAT ซื้อ 12 เดือน · ปริมาณซื้อเนื้อสัตว์แยกชนิด(รายชื่อจากที่ user ลงไว้ ไม่ fix เลือกเพิ่ม/ลดได้) · เทียบค่าใช้จ่ายส่วนตัว vs งบสรรพากร · Top 5 ร้านเดือนนี้
- **เงินออกเพิ่ม = สื่อว่า "ค่าใช้จ่ายสูงขึ้น" ห้ามใช้สี/ลูกศรที่ดูเป็นเรื่องดี / ห้ามแสดงรายได้ กำไร (ยังไม่มีข้อมูล)**
- query สรุปจากฝั่งสมอง ไม่ดึงข้อมูลดิบมาคำนวณหน้าจอ

### ▶ กระบวนการ H: จัดการข้อมูลแม่ (หน้า Data)
- **จัดการร้าน (supplier):** เพิ่ม / แก้ไข / ลบ(soft-delete ถ้ามีรายการอ้างถึง) / เปลี่ยนชื่อ-โลโก้-ค่าส่ง-ค่าลัง-เช็คลิสต์เอกสาร / สลับตำแหน่ง (ลากหรือปุ่มเลื่อน)
- **จัดการสินค้าของแต่ละร้าน (vendor_items):** เพิ่ม / แก้ไข / ลบ / สลับตำแหน่ง — แก้ได้ทุกฟิลด์ (ชื่อ, สเปค, หน่วยขาย, ขนาดแพ็ก, NW%, ราคา, รูป)
- ร้านสินค้าเยอะ(Makro) → สร้าง/แก้/ลบหมวดภายในร้านได้ (เช่น หมู/ไข่+เต้าหู้/ผัก+อื่นๆ/เครื่องปรุง) + จัดสินค้าเข้าหมวด + หน้าเลือกสินค้ามีแถบกรองตามหมวด
- **mapping SKU→วัตถุดิบมาตรฐาน** (จับ "กุ้ง 16/20"→"กุ้งใหญ่") ทำที่นี่ที่เดียว — App_stock/App_recipe อ่าน mapping เดียวกัน ห้ามให้แต่ละแอปทำตารางแปลงเอง
- ต้นทุนแท้ = ราคา ÷ NW% (คำนวณให้ ใช้ฝั่งวิเคราะห์ — บัญชีลงเต็มตามสลิป)
- แก้รูปได้ทุกจุด (อัปโหลด → บีบ WebP อัตโนมัติ)

### ▶ กระบวนการ I: แก้ไข (ทุกรายการ)
ทุกรายการมีปุ่มแก้ + ดูประวัติ: เปลี่ยนรูป / เปลี่ยนเส้นทาง(กลับ A4) / แยกการจับคู่ / แก้หมวด — ตามกฎข้อ 4 (แก้ทับ/reversal/ใบใหม่) + sync ไฟล์ Drive ตาม
