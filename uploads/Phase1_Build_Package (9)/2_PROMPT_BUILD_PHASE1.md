## ★ เส้นทางหลัก: บันทึกการซื้อ (สำคัญสุด — อ่านก่อน) ★
═══════════════════════════════════════════════════════════
เส้นทางหลัก = **เลือกจากข้อมูลแม่ (master data)** ไม่ใช่ให้ AI อ่านรูปเป็นตัวตั้ง ผู้ใช้เดินทีละขั้น:

**ขั้น 1 — เลือกร้าน (Supplier)**
กริดการ์ดโลโก้ร้าน เรียงร้านที่ซื้อบ่อยขึ้นก่อน + ช่องค้นหา + ปุ่ม "เพิ่มร้านใหม่" (กรอกสั้นๆ ใช้ได้ทันที ไม่บังคับไปหน้า Data ก่อน)

**ขั้น 2 — เลือกสินค้า + ใส่ปริมาณ**
พอเลือกร้าน → โชว์การ์ดสินค้าของร้านนั้น (จากตาราง vendor_items) แต่ละการ์ดมี: รูป, ชื่อ, **สเปคกำกับ** (เช่น "16/20 · NW80% · ฿275/กก."), ราคาล่าสุด, ปุ่ม − / + ปรับจำนวน
- ราคาโชว์อัตโนมัติจากที่จำไว้ — แตะแก้ได้ → ถ้าแก้ ถาม "บันทึกเป็นราคาใหม่ของร้านนี้ไหม?" (ตอบใช่ = เก็บลง price history)
- แถบล่างรวมยอดวิ่งสดทุกครั้งที่กด +/−
- สินค้าใหม่ยังไม่มีในร้าน → ปุ่ม "เพิ่มสินค้าด่วน"

**ขั้น 3 — ค่าส่ง + ค่าลังโฟม**
เด้งขึ้นมาอัตโนมัติจากค่า default ของร้านนั้น (vendors.default_shipping_cost, default_box_cost_per_box) — แก้ได้ทุกครั้ง (ร้านแชทค่าส่ง/ค่าลังไม่เท่ากันแต่ละครั้ง)

**ขั้น 4 — แนบภาพ/หลักฐานการซื้อ (เช็คลิสต์เอกสาร)**
โชว์เช็คลิสต์เอกสารตามที่ร้านนี้ต้องมี (vendors.doc_checklist) เป็นช่องๆ เช่น ร้านแชท = [แคปสั่งของ][สลิปโอน][รูปของ] / Makro = [ใบกำกับภาษี]
- แต่ละช่อง = ปุ่มถ่าย/เลือกไฟล์ มีแล้วติ๊กเขียว ยังไม่มีเป็นเทา
- **ครบ → ปุ่ม "ส่งเข้าระบบ" / ไม่ครบ → ปุ่ม "บันทึกร่าง (รอเอกสาร)"** ร่างไปรออยู่ตะกร้ารอจับคู่ เติมเอกสารที่ขาดทีหลังได้ (ของกับบิลมาคนละวันได้ never block)

**ขั้น 5 — จอสรุป → ยืนยัน** (รายละเอียดช่วงคัดกรอง/เอกสาร/บัญชี ดู 3 ช่วงข้างล่าง)

**AI vision = ผู้ช่วยกรอกเท่านั้น** ไม่ใช่เส้นทางหลัก — มีปุ่ม "ให้ AI อ่านจากรูป" ไว้ตอนบิลยาวๆ (เช่นใบ Makro หลายรายการ) กดแล้ว AI เติมฟอร์มให้ คนตรวจ/แก้ก่อนยืนยัน เข้ากระบวนการเดียวกับกรอกมือ
**ค่าใช้จ่ายที่ไม่ใช่สินค้า** (ค่าไฟ/ค่าเช่า/เบ็ดเตล็ด): ทางลัดแยก ไม่ต้องผ่านการเลือกสินค้า

## ★ ช่วงที่ 1: การคัดกรอง (ตัวกำหนดทุกอย่างหลังจากนี้) ★
═══════════════════════════════════════════════════════════
คัดกรอง = ถามให้พอรู้ว่า "เอกสารเดินไปทางไหน" — **ระบบไม่เดา ทุกทางมีกฎตายตัว** ผู้ใช้ตอบ ระบบ run

**หน้าจอแสดงเป็นข้อความเต็มเสมอ ห้ามโชว์รหัส 1a/1b/2a/2b ให้ผู้ใช้เห็น** (รหัสใช้แค่ในฐานข้อมูล)
**คำถามหลักข้อเดียว: "เอกสารจากผู้ขายเป็นแบบไหน?"** → 4 การ์ด (ข้อความเต็ม):
- **มีใบกำกับภาษี (มี VAT)** → ไม่สร้างเอกสารเพิ่ม + แยกภาษีซื้อเก็บไว้ (ใช้ในงบจำลอง) — route=1a
- **มีบิล/ใบเสร็จ (ไม่มี VAT)** → ไม่สร้างเอกสารเพิ่ม — route=1b
- **มีแค่สลิปโอน** (~90% ของเคส) → สร้าง "ใบสำคัญจ่าย" (ชื่อผู้รับจากสลิป) + แนบสลิป — route=2a
- **ไม่มีเอกสารเลย** (route=2b) → เอกสารที่สร้างขึ้นกับ"วิธีจ่าย" ไม่ใช่กับคำว่าค่าเดินทาง:
  - **จ่ายด้วยการโอน (มีสลิป พิสูจน์ผู้รับได้)** → "ใบสำคัญจ่าย" + แนบสลิป → ลงภาษีได้ (เหมือน 2a)
  - **จ่ายสด ไม่มีตัวผู้รับให้พิสูจน์** (แท็กซี่/วิน/ค่าเดินทางเล็กน้อย) → "ใบรับรองแทนใบเสร็จ" (พนักงานรับรองเอง) → ลงภาษีได้
  - **จ่ายสด + ไม่ใช่ค่าเดินทาง + พิสูจน์ผู้รับไม่ได้** → tag `inhouse_only` → เข้าเฉพาะงบส่วนตัว **ห้ามเข้างบจำลองสรรพากร** (ระบบกันอัตโนมัติ)
  - หลักคือ: มีสลิปเมื่อไหร่ = ใบสำคัญจ่าย / ไม่มีอะไรพิสูจน์ผู้รับแต่เป็นรายจ่ายจริงของกิจการ = ใบรับรองแทนใบเสร็จ / พิสูจน์ไม่ได้เลย = ลงได้แค่งบส่วนตัว

**การช่วยของ AI:** AI ดูรูปแล้วติ๊กทางที่น่าจะใช่ให้ล่วงหน้า (เห็น VAT ติ๊ก 1a ให้) ผู้ใช้แค่ยืนยันหรือแตะเปลี่ยน — ถ้าไม่มีรูป (คีย์มือ) ผู้ใช้เลือกเอง
**เตือนนุ่มๆ:** ถ้าเลือก 2b + จ่ายเงินสด → "ถ้าโอนได้แนะนำโอน จะได้ลงภาษีได้" (ดันให้เข้า 2a ซึ่งดีกว่า)
**flag ของถาวร:** ถ้า AI สงสัยว่าเป็นอุปกรณ์/ของถาวร (ตู้เย็น) ถาม ใช่/ไม่ใช่ — **เฟส 1 แค่บันทึก flag ลงตาราง assets ไม่คำนวณค่าเสื่อม** ลงเป็นค่าใช้จ่ายทันทีทั้ง 2 งบ (เก็บ flag ไว้เปิดค่าเสื่อมทีหลัง)

## ★ ช่วงที่ 2: การสร้างเอกสาร ★
═══════════════════════════════════════════════════════════
เมื่อข้อมูลครบตาม route ระบบ gen เอกสารตามชนิดที่ช่วงคัดกรองกำหนด — ฟิลด์บังคับตามคู่มือกรมสรรพากรมีดังนี้
**หลัก never block กับฟิลด์บังคับ อยู่ด้วยกันได้ด้วยการแยกจังหวะ:**
- **ตอนร่าง (draft):** ขาดฟิลด์ได้ บันทึกร่างไว้ก่อน + ระบบ mark ว่าขาดอะไร (ไม่หยุดผู้ใช้)
- **ตอนยืนยัน/เซ็น:** ต้องครบทุกฟิลด์บังคับ ถ้ายังขาด ระบบบอกชัดว่าขาดช่องไหน กดเซ็นไม่ได้จนกว่าจะเติม (จุดนี้ block ได้ เพราะเป็น deadline กับคนภายนอก=สรรพากร)
ฟิลด์บังคับต่อเอกสาร:

**ใบสำคัญจ่าย (Payment Voucher)** — สำหรับทุกกรณีที่ "จ่ายด้วยการโอน มีสลิป" (2a และ 2b ที่โอน):
ชื่อ-ที่อยู่-เลขผู้เสียภาษี/บัตรปชช.ผู้รับ · วันที่จ่าย · ประเภทรายการ+จำนวนเงิน (รายการละบรรทัด) · ช่องลายมือชื่อผู้รับเงิน · ลายมือชื่อผู้อนุมัติ(=owner) · **แนบหลักฐานจ่ายเสมอ (สลิป)** · บัตรปชช.เฉพาะจ่ายเงินสด

**ใบรับรองแทนใบเสร็จรับเงิน** — สำหรับ 2b ที่ "จ่ายสด ไม่มีตัวผู้รับให้พิสูจน์" (แท็กซี่/วิน/ค่าเดินทางเล็กน้อย):
ตาราง วันที่/รายละเอียด/จำนวนเงิน · ยอดรวม+**ตัวอักษรไทย** · ข้อความรับรองตามแบบ ("ขอรับรองว่ารายจ่ายข้างต้นไม่อาจเรียกใบเสร็จจากผู้รับได้ และจ่ายไปในงานกิจการโดยแท้...") · ลงชื่อผู้เบิกจ่าย+ผู้อนุมัติ

**กติกา:** แปลงเลขเป็นตัวอักษรไทยอัตโนมัติ / บิลชื่อคนอื่น (ค่าน้ำ-ไฟคอนโด) ผูกสัญญาเช่า+หลักฐานกิจการจ่ายจริง / ทุกเอกสารสถานะ draft รอ owner เซ็น (ช่วงถัดไป) / 1a,1b ไม่ต้องสร้าง (เอกสารร้านคือหลักฐานแล้ว)
**ลายเซ็น:** owner batch approve → ลายเซ็นแปะ **เมื่อกดยืนยันเท่านั้น** + log(ใคร/เวลา/hash เอกสาร) ห้ามแปะอัตโนมัติ / เซ็นแล้วแก้ไม่ได้ ต้องออกใบใหม่แทน(ใบเก่า void)

## ★ ช่วงที่ 3: บันทึกบัญชี → งบ 2 ชุด ★
═══════════════════════════════════════════════════════════
ทุก event ระบบลง **บัญชีคู่อัตโนมัติหลังบ้าน (เดบิต=เครดิต)** ผู้ใช้ไม่เห็น ไม่ต้องรู้ — ทุก journal line ติด **book_scope**:
- `both` = เข้าทั้ง 2 งบ (รายการที่มีเอกสารครบ: 1a/1b/2a/2b-เดินทาง)
- `inhouse_only` = เข้าเฉพาะงบส่วนตัว (2b อื่นๆ / รายการไม่มีเอกสารพิสูจน์ผู้รับ)

**งบชุดที่ 1 — งบส่วนตัว (ดูเอง / วิเคราะห์จริง)**
รวม journal line **ทุกอัน** ไม่สนว่ามีบิลหรือไม่ → เห็นภาพเงินจริง:
- P&L: รายได้ − ต้นทุน − ค่าใช้จ่าย = **กำไรจริงของร้าน**
- Cashflow: เงินเข้า − เงินออกจริง
- asset ลงค่าใช้จ่ายทันที (จ่ายแล้วคือจ่ายแล้ว ไม่มีค่าเสื่อมกวนใจ)
→ นี่คืองบที่คุณใช้ตัดสินใจบริหารประจำวัน

**งบชุดที่ 2 — งบจำลองถ้าจดนิติ (สำหรับประเมินภาษี)**
กรองเฉพาะ book_scope=`both` (รายการเอกสารครบเท่านั้น) → จำลองว่าถ้าเป็นนิติบุคคลจะเป็นยังไง:
- P&L แบบนิติ (เฉพาะรายจ่ายที่มีหลักฐานลงภาษีได้)
- **ตาราง VAT: ภาษีซื้อ (จาก 1a) − ภาษีขาย = ต้องจ่าย/ขอคืนเท่าไหร่**
- **สำคัญ — งบนี้ยังไม่สมบูรณ์โดยตั้งใจ:** ต้นทุนขาย (COGS) ที่แท้จริงต้องรอ App_stock ลงข้อมูลการเบิกใช้จริงก่อน เฟสนี้ App_stock ยังไม่เชื่อม → **งบชุดนี้จึงลงได้เท่าที่ข้อมูลมี** = เห็น "ค่าใช้จ่ายฝั่งซื้อ" กับ "เงินไหลออก (cash outflow)" ได้ชัดแล้ว แต่ COGS/กำไรสุทธิยังไม่ครบจนกว่า stock จะต่อ
- ให้แสดงหมายเหตุในงบนี้ว่า "ตัวเลขต้นทุนขายจริงรอเชื่อม App_stock — ปัจจุบันแสดงเท่าที่มีข้อมูล"
→ แค่นี้ก็พอเห็นแนวโน้มภาระภาษีถ้าจด หจก. และเป็นฐานที่ต่อยอดได้ทันทีเมื่อ stock เชื่อม

**ทั้ง 2 งบมาจาก journal ชุดเดียวกัน ต่างแค่ filter** → ไม่มีการลงซ้ำ ไม่มีทางไม่ตรงกัน

## ★ หน้า Dashboard (แยกต่างหาก — ภาพรวมการเงินฝั่งซื้อ) ★
═══════════════════════════════════════════════════════════
หน้ารวมกราฟ/ตัวเลขสรุป ทุกค่าคำนวณจริงจากฐานข้อมูล (journal/payments/vat/vendor_items) ห้าม hardcode:

**การ์ดตัวเลขด้านบน (ดูแวบเดียว):**
- **เงินไหลออกเดือนนี้** (cash out รวมของเดือนปัจจุบัน ตัวเลขใหญ่)
- **งานค้าง**: รออนุมัติ N รายการ · ค้างรับ N · ของขาดรอเคลียร์ N (แตะเข้าไปดูรายการได้)

**กราฟ/ตาราง:**
1. **กราฟแท่ง ค่าใช้จ่ายรายเดือน ย้อนหลัง 12 เดือน** — เดือนปัจจุบันเป็นสีเด่นกว่าเดือนอื่น
2. **กราฟแท่ง VAT ซื้อ รายเดือน ย้อนหลัง 12 เดือน** — เดือนปัจจุบันสีเด่น (จาก vat_lines type=input)
3. **กราฟปริมาณซื้อเนื้อสัตว์แยกชนิด** (อกไก่/สันในไก่/เนื้อแดงวัว/หมูสันนอก/หมูสันใน/แซลมอน ฯลฯ) — **รายชื่อชนิดมาจากวัตถุดิบมาตรฐาน (items) ที่ user เคยลงข้อมูล/รูปไว้ ไม่ hardcode** มีตัวเลือกติ๊กเพิ่ม/ลดชนิดที่อยากเห็นได้ (semi-manual) — ปริมาณรวมจาก vendor_items ที่ map เข้าชนิดนั้น
4. **กราฟเทียบ ค่าใช้จ่ายส่วนตัว (งบวิเคราะห์) vs ค่าใช้จ่ายตามงบส่งสรรพากร (งบจำลอง)** — 2 แท่ง/2 เส้นต่อเดือน เห็นส่วนต่างชัด (ส่วนต่าง = รายการที่ไม่มีเอกสารครบ ลงภาษีไม่ได้)
5. **Top 5 ร้านที่จ่ายเยอะสุดเดือนนี้** — แถวสั้นๆ (โลโก้ร้าน + ยอด) ไม่ต้องกราฟ

ทุกกราฟ: แตะแท่ง/จุดเพื่อดูตัวเลข / เลือกช่วงเวลาได้ / empty state ถ้ายังไม่มีข้อมูล / โหลดเร็ว (query สรุปฝั่งสมอง ไม่ดึงดิบมาคำนวณหน้าจอ)

## แนวทางออกแบบ UI (ไม่ล็อกแบบ — ยึดหลักแล้วออกแบบเอง)
- ผู้ใช้ = เจ้าของร้าน 2 คน ไม่ใช่สายเทคนิค **ความง่าย+ความน่ารักสำคัญที่สุด — ถ้าออกมาเป็นตารางแถว dropdown เป็นพรืดแบบ Excel = ล้มเหลว ผู้ใช้ไม่ใช้**
- ยึดความคุ้นเคยจากแอปสั่งอาหาร/Shopee: เลือกร้าน=กริดโลโก้, เลือกสินค้า=การ์ดรูป+ปุ่ม −/+, รวมยอดวิ่งแถบล่าง, แนบเอกสาร=ช่องติ๊กเขียว
- อารมณ์ภาพ: อบอุ่น เป็นมิตร เหมาะร้านอาหาร ดูแล้วสบายตาไม่น่ากลัว — **เลือกโทนสี/สไตล์การ์ดเองได้เต็มที่** (ไม่ล็อกสี) ขอแค่ใช้มาสคอต/ตัวละครจาก assets ที่แนบประกอบ / Mobile-first 390px ปุ่ม≥48px font≥16px การ์ดแนวตั้ง ห้าม scroll แนวนอน / เปิดกล้องทันที
- ทุกหน้า loading + empty + error ภาษาไทยคนธรรมดาอ่านรู้เรื่อง / เมนูล่าง 5 ช่องแนะนำ: หน้าหลัก·รายการ·สแกน(กลาง)·ร้านค้า·ตั้งค่า

## หน้าจอที่ต้องมี (หน้าตาออกแบบเอง — ฟังก์ชันครบ)
หน้าแรก(สถานะค้าง 4 กลุ่มนับจริง+4 ทางเข้า+ล่าสุด) · ถ่าย/สแกน(บันทึกไม่มีรูปได้) · คัดกรอง(ช่วง1) · ตรวจ/แก้ข้อมูล · ถามของถาวร · **สร้างรายการซื้อ(เส้นทางหลัก 5 ขั้นข้างบน)** · สลิปหลายร้าน · ตะกร้ารอจับคู่ · รับของ · ของขาด(ส่งเติม/คืนเงิน/loss) · สรุปก่อนบันทึก · อนุมัติ+เซ็น(owner) · รายการทั้งหมด(แก้ทุกอย่าง+ประวัติ) · **งบ 2 ชุด(ช่วง3)** · **Dashboard(ภาพรวม 5 กราฟ+การ์ดงานค้าง)** · ตั้งค่า · **หน้า Data**(จัดการร้าน+default, สินค้าต่อร้าน vendor_items, จับคู่ SKU→วัตถุดิบมาตรฐาน, ประวัติราคา) · ฟอร์มคีย์มือ

## กติกาทุกจอ
Never block ตอนเก็บ/ร่าง (ไม่ชัวร์=บันทึก+mark ไม่หยุดผู้ใช้) — **ยกเว้นจุดยืนยัน/เซ็นเอกสารที่ต้องมีฟิลด์บังคับครบ** (block ได้เพราะเป็น deadline กับสรรพากร) / แก้ได้ทุกรายการ+ประวัติ (ยังไม่ลงบัญชี=แก้ทับ / ลงแล้ว=reversal / เซ็นแล้ว=ใบใหม่) ห้าม DELETE เงิน / try-catch ทุก call→toast ไทย ห้ามจอขาว / ตัวเลขคำนวณจริงห้าม hardcode / ตัวละคร-ไอคอนจาก assets ที่แนบเท่านั้น

## ลำดับการทำงาน
1. tools→ตารางเต็ม+RLS+seed→schema.sql
2. สมอง: files/drive → line-auth → process-file(AI ผู้ช่วย) → route(คัดกรอง) → matching → journal(คู่+book_scope) → vat → documents → signing → reports(งบ 2 ชุด)
3. หน้าจอ: เส้นทางซื้อหลัก(5 ขั้น) ให้ใช้ได้ก่อน → คัดกรอง/ตรวจ/สรุป → สลิปหลายร้าน/รับของ/ของขาด/จับคู่ → เอกสาร+เซ็น → รายการ/งบ 2 ชุด/ตั้งค่า/หน้า Data → คีย์มือ
4. SETUP.md(LINE, Google, Claude API, SlipOK — จับมือทำ) + README แผนที่
