## A. หลักการเฟส 1 (5 ข้อ)
1. **ทำเท่าที่ใช้ แต่เก็บข้อมูลดิบครบ** — ตัดได้เฉพาะ "การประมวลผล/หน้าจอ" ห้ามตัด "การเก็บข้อมูลดิบ" (ข้อมูลที่ไม่เก็บวันนี้กู้คืนไม่ได้ / โค้ดที่ไม่เขียนวันนี้ค่อยเขียนได้)
2. **ลงบัญชีคู่หลังบ้านตั้งแต่แรก แต่ซ่อนจากผู้ใช้** — เดบิต-เครดิตเกิดอัตโนมัติ ผู้ใช้ไม่เห็น ไม่ต้องรู้ (เพราะ P&L + แยก VAT ที่ต้องการ ประกอบจากบัญชีคู่ ถ้าลงมั่วจะต่อยอดไม่ได้ ต้องรื้อ)
3. **งบ 2 ชุด:** ① วิเคราะห์ (Cashflow/P&L ดูเอง — บันทึกทุกอย่างไม่สนบิล) ② จำลอง "ถ้าจดนิติ" (กรองเฉพาะรายการเอกสารครบ + แยก VAT ซื้อ-ขาย → เห็นภาระภาษีถ้าเป็นนิติ)
4. **Never block / แก้ได้เสมอ / ไม่ลบของเดิม (reversal)** — เหมือนเดิม
5. **สมองเดียวหลายประตู** — logic อยู่ Edge Functions ประตู LINE เป็นเปลือก (เผื่อ webapp มาต่อ)

## B. ประตูคัดกรอง (เฟส 1 ใช้เต็ม)
ถ่าย/อัปโหลด/คีย์ → ถาม "เอกสารแบบไหน?" 4 ทาง:
- **มีใบกำกับภาษี (มี VAT)** → เก็บ + แยก VAT ซื้อ (ใช้ในงบชุดจำลอง) — [รหัสหลังบ้าน: 1a]
- **มีบิล/ใบเสร็จ (ไม่มี VAT)** → เก็บ — [1b]
- **มีแค่สลิปโอน** (~90%) → สร้างใบสำคัญจ่าย + แนบสลิป — [2a]
- **ไม่มีเอกสารเลย** → ตามวิธีจ่าย: โอน=ใบสำคัญจ่าย / จ่ายสดไม่มีผู้รับพิสูจน์=ใบรับรองแทนใบเสร็จ / พิสูจน์ไม่ได้=tag inhouse_only (เข้างบวิเคราะห์เท่านั้น) — [2b]
> หมายเหตุ: รหัส 1a/1b/2a/2b เป็นชื่อ route ในฐานข้อมูลเท่านั้น **หน้าจอต้องแสดงเป็นข้อความเต็ม** ("มีใบกำกับภาษี" ฯลฯ) ห้ามโชว์รหัสให้ผู้ใช้เห็น
+ **flag is_asset**: ถามเมื่อ AI สงสัยว่าเป็นของถาวร → **เฟส 1 แค่บันทึก flag ไว้ ไม่คำนวณค่าเสื่อม** (ลงค่าใช้จ่ายทันทีทั้ง 2 งบ) — เก็บ flag ไว้เปิดฟีเจอร์ค่าเสื่อมทีหลังโดยไม่ต้องรื้อ

## C. Flow จับคู่ (เฟส 1 ใช้เต็ม)
รายการซื้อ (purchase) เป็นจุดเกาะ สร้างได้ 3 ทาง (แคป/สลิป/กรอกเอง) ไม่บังคับ / สลิป/ของ/บิล มาเกาะเมื่อไหร่ก็ได้ / สลิปหลายร้านแตกบรรทัด / ของขาด→คิดเป็นเงินรอ (ส่งเติม→สินค้า / คืนเงิน→เงิน / ไม่ได้→loss)

## D. บัญชีหลังบ้าน (เฟส 1 — ลงคู่ ซ่อนไว้)
ทุก event ลง journal_entries/lines อัตโนมัติ (เดบิต=เครดิต) ทุก line มี **book_scope**:
- `both` = เข้าทั้ง 2 งบ (รายการปกติที่มีเอกสาร)
- `inhouse_only` = เข้าเฉพาะงบวิเคราะห์ (2b อื่นๆ / รายการไม่มีเอกสาร)

**งบชุด ① วิเคราะห์ (ดูเอง):** รวมทุก journal line → P&L (รายได้-ต้นทุน-ค่าใช้จ่าย = กำไรจริง) + Cashflow (เงินเข้า-ออกจริง) — สะท้อนการดำเนินงานจริง ไม่ตามกฎภาษี asset ลงทันที
**งบชุด ② จำลองถ้าจดนิติ:** กรองเฉพาะ book_scope=both (เอกสารครบ) → P&L แบบนิติ + **ตาราง VAT: ภาษีซื้อ (จาก 1a) − ภาษีขาย = ต้องจ่าย/ขอคืนเท่าไหร่** → ประเมินภาระภาษีถ้าเป็นนิติเต็มตัว

**Yield/ของหาย (น้ำแข็งละลาย ผัดหด ตักเกิน แถม เสีย) — ใช้ true-up ไม่ไล่ตามทุกกรัม:** ซื้อลงเต็มตามสลิป → ตัดต้นทุนตามเบิกใช้ → นับสต๊อกจริงเป็นระยะ → ส่วนต่าง "ควรเหลือ vs เหลือจริง" ลงบัญชี 5110 ของเสีย/สูญหาย ก้อนเดียว → งบตรงเสมอโดยไม่ต้องรู้ว่าหายตอนไหน / standard yield % ต่อวัตถุดิบเก็บเป็นฟิลด์ไว้ (loss report เชิงลึก = เฟสท้าย ฝั่ง App_recipe)

**เฟส 1 ไม่ทำ (แต่ข้อมูลพร้อม):** ค่าเสื่อม, ปิดงบ CPA, งบดุลเต็ม, ปฏิทิน/ยื่นภาษี, loss report จาก yield — เปิดทีหลังจาก journal + flag + ฟิลด์ที่เก็บไว้

## E. ตาราง (สร้าง "เต็ม" ตั้งแต่เฟส 1 — ฐานไม่ต้องรื้อ)
สร้างครบทุกตารางแม้ฟีเจอร์ยังไม่ใช้ (คอลัมน์ที่ยังไม่ใช้ปล่อยว่างได้):
**พื้นฐาน:** entities · users(line_user_id,is_owner) · vendors(+ค่าจำ: default_expense_account, default_entity_id, default_route, **default_shipping_cost, default_box_cost_per_box, doc_checklist** [เอกสารที่ต้องมีของร้านนี้ เช่น แชท=แคป+สลิป+รูปของ / Makro=ใบกำกับ]) · **vendor_items (SKU ตามหน้าร้านจริง: vendor_id, ชื่อเต็มตามร้าน, spec เช่น 16/20, sell_unit กก./แพ็ค/ตัว, pack_size เช่น 800g, nw_percent, ราคาล่าสุด, maps_to_item_id)** · items(category_path, **std_yield_percent** *เก็บไว้ ยังไม่ประมวลผล*) · accounts(ผังบัญชี) · depreciation_rules *(เก็บไว้ ยังไม่ใช้)*

**หลัก 2 ชั้น SKU↔วัตถุดิบ:** ฝั่งซื้อบันทึกเป็น vendor_items (สเปคจริงของร้าน เช่น กุ้งผ่าหลัง 16/20 NW80% ฿275/กก.) → map เข้า items มาตรฐาน (กุ้งใหญ่/กลาง/เล็ก) ที่ App_stock/App_recipe ใช้ — **mapping ทำที่ตารางกลางนี้ที่เดียว ห้ามให้แต่ละแอปไปทำตารางแปลงชื่อเอง** / ต้นทุนแท้ต่อหน่วยใช้ได้ = ราคา ÷ NW% (ระบบคำนวณให้ ใช้ฝั่งวิเคราะห์/สูตร — บัญชียังลงเต็มตามสลิป)
**ขาเข้า+จับคู่:** captures · match_groups(required_parts/collected_parts)
**หัว-บรรทัด:** purchases + purchase_lines · payments + payment_lines · receipts + receipt_lines
**บัญชี:** journal_entries · journal_lines(+book_scope) — งบทุกตัวมาจากที่นี่
**สินทรัพย์:** assets(is_asset, depre_rule_id) *(เก็บ flag ตอนซื้อ ยังไม่คำนวณค่าเสื่อม)*
**เอกสาร+ไฟล์:** documents(type,doc_no,status,replaces_id) · files(sha256,thumb_supabase_path,original_gdrive_id,drive_sync_status) · signature_events
**กันพัง:** edit_history · auto_decisions · number_sequences(row-lock)
**VAT:** vat_lines(entry_id, type input/output, base, vat) — ป้อนจาก 1a และรายได้ ใช้ทำตาราง VAT ในงบชุด ②

## F. เอกสาร + จัดเก็บ (เฟส 1 ใช้เต็ม)
สเปคใบสำคัญจ่าย/ใบรับรองตามคู่มือกรมสรรพากร (ฟิลด์ครบ + ตัวอักษรไทย) + ลายเซ็น (action จริง + hash) / ต้นฉบับ → Google Drive (กิจการ/ปี/เดือน/CASE) / Supabase = WebP thumbnail เท่านั้น / เก็บ ≥5 ปี
