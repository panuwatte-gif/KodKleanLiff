# สร้าง KodKlean LIFF — ระบบการเงินฝั่งซื้อ (Phase 1)
สร้างเว็บแอปในกรอบ LINE LIFF สำหรับร้านอาหาร ใช้ asset รูปในโฟลเดอร์นี้ (ดู ASSET_INDEX.md) — **ห้ามสร้างรูปเอง หยิบจากที่ให้มาเท่านั้น** จุดที่ไม่มีรูปให้ใช้ไอคอนเวกเตอร์เรียบๆแทนได้

⚠️ มี Supabase MCP tools (execute_sql, apply_migration, deploy_edge_function, storage) — ตรวจ tool list ก่อน (tool_search "supabase") สร้างตารางและ backend จริง ห้ามบอกว่าทำไม่ได้ก่อนลองค้น

## เป้าหมายและผู้ใช้
เจ้าของร้านอาหาร (ไม่ใช่สายเทคนิค, ใช้ Android 100%) ถ่ายบิล/สลิป → ระบบเก็บหลักฐาน สร้างเอกสาร ลงบัญชีให้อัตโนมัติ เพื่อทำบัญชีให้เรียบร้อยและประเมินภาษีถ้าจดนิติ
Phase 1 = **ฝั่งซื้อและเงินออกเท่านั้น** ยังไม่มีข้อมูลรายได้/ยอดขาย

## หลักสถาปัตยกรรม (สำคัญ)
- **สมองเดียวหลายประตู:** business logic ทั้งหมด (คัดกรอง, จับคู่, ลงบัญชีคู่, สร้างเอกสาร, จัดการไฟล์) อยู่ใน Supabase Edge Functions — หน้าจอเป็นเปลือกเรียก API เท่านั้น (ภายหลังจะมี webapp มาต่อสมองเดิม)
- Vanilla JS + ES Modules แยกไฟล์ชัด ไม่ใช้ framework — เจ้าของแก้เองไม่ได้ ต้องให้ AI ตัวอื่นมาแก้ต่อง่าย
- ทุกอย่าง "ไม่บล็อกตอนเก็บ/ร่าง" แต่ "ต้องครบตอนยืนยัน/เซ็นเอกสาร" / แก้ไขได้เสมอ ไม่ลบของเดิม (ใช้ reversal/void)

## แนวทาง UI
- **การ์ดเรียบ สะอาด กดง่าย แนวแอปสั่งอาหาร/ช้อปปิ้งที่คนไทยคุ้น** — เลือกร้าน=กริดโลโก้, เลือกสินค้า=การ์ดรูป+ปุ่ม −/+, รวมยอดวิ่งแถบล่าง, แนบเอกสาร=ช่องติ๊ก
- **ห้ามทำเป็นฉากภาพประกอบเต็มจอ/ตัวการ์ตูนครึ่งจอ** (ทำจริงแล้วรก กดยาก) — ตัวการ์ตูน/มาสคอตใช้ประกอบพอดีๆ ไม่บังปุ่ม
- อารมณ์: สวยงาม น่ารักมาก สีสันหลากหลาย สดใส — แต่ยังอ่านตัวเลขการเงินง่าย
- ตัวการ์ตูนอาเฮีย+แม่พันใช้ **คู่วัยเดียวกัน** กระจายวัยในแต่ละหน้า ไม่ซ้ำ (ดู ASSET_INDEX)
- Mobile-first กว้าง 390px, ปุ่ม ≥48px, ฟอนต์ ≥16px (ใช้ Noto Sans Thai), ไม่มี status bar จำลอง, optimize สำหรับ Chrome Android + LINE Android

## หน้าจอ (ฟังก์ชันต้องครบ — ออกแบบหน้าตาเอง)
**เส้นทางหลัก บันทึกซื้อ (5 ขั้น):**
1. เลือกร้าน (กริดโลโก้ ร้านบ่อยขึ้นก่อน + ค้นหา + เพิ่มร้านใหม่)
2. เลือกสินค้า (การ์ดรูป+สเปค เช่น "16/20 · NW80% · 275/กก." ปุ่ม −/+ ราคาจากฐานข้อมูลแก้ได้→ถามบันทึกราคาใหม่ / รวมยอดวิ่ง)
3. ค่าส่ง+ค่าลังโฟม (เด้งจากค่าประจำร้าน แก้ได้)
4. แนบเอกสาร (เช็คลิสต์ตามร้าน เป็นช่องถ่าย/เลือกไฟล์ ครบ→ส่งเข้าระบบ / ไม่ครบ→บันทึกร่างรอเอกสาร)
5. สรุป→ยืนยัน

**คัดกรองเอกสาร:** คำถาม "เอกสารจากผู้ขายเป็นแบบไหน" 4 การ์ด **ข้อความเต็ม ห้ามโชว์รหัสย่อ**: "มีใบกำกับภาษี(มี VAT)" / "มีบิลใบเสร็จ(ไม่มี VAT)" / "มีแค่สลิปโอน"(พบบ่อยสุด) / "ไม่มีเอกสารเลย" — AI ช่วยติ๊กให้ก่อนจากรูป คนยืนยัน/เปลี่ยน / เลือก"ไม่มีเอกสาร"→ถามต่อวิธีจ่าย (โอน=ใบสำคัญจ่าย / สดพิสูจน์ผู้รับไม่ได้=ใบรับรองแทนใบเสร็จ / พิสูจน์ไม่ได้เลย=ลงได้แค่งบส่วนตัว)

**หน้าอื่น:** หน้าแรก(งานค้าง 4 กลุ่มนับจริง+4 ทางเข้า+ล่าสุด) · ถ่าย/สแกน(บันทึกไม่มีรูปได้, AI ช่วยอ่าน) · ตรวจ/แก้ข้อมูลที่ AI อ่าน · ถามของถาวร(แค่บันทึก flag) · สลิปเดียวหลายร้าน(แตกบรรทัด ผลรวม=ยอดสลิป) · ตะกร้ารอจับคู่ · รับของ(แถวเรียบ ช่องรับจริง default=สั่ง ถ่ายรูปของ) · ของขาด(คิดเป็นเงินจริง→ส่งเติม/คืนเงิน/loss) · อนุมัติ+ลายเซ็น(owner, ลายเซ็นแปะเมื่อกดยืนยัน) · รายการทั้งหมด(ค้น/กรอง+แก้ไข+ประวัติ) · ฟอร์มคีย์มือ

**Dashboard (แยกหน้า):** การ์ดเงินไหลออกเดือนนี้ + งานค้าง(รออนุมัติ/ค้างรับ/ของขาด) + กราฟ: ค่าใช้จ่าย 12 เดือน(เดือนนี้สีเด่น) · VAT ซื้อ 12 เดือน · ปริมาณซื้อเนื้อสัตว์แยกชนิด(รายชื่อจากที่ user ลงไว้ ไม่ fix) · เทียบค่าใช้จ่ายส่วนตัว vs งบสรรพากร · Top 5 ร้าน — **สื่อว่าเป็น "ฝั่งซื้อ+เงินออก" ห้ามโชว์รายได้/กำไร, เงินออกเพิ่ม=สื่อว่า"ค่าใช้จ่ายสูงขึ้น"ห้ามใช้สีเขียวเหมือนเรื่องดี**

**หน้า Data (จัดการข้อมูลแม่):** เพิ่ม/แก้/ลบ(soft-delete)/สลับตำแหน่ง ทั้งร้านและสินค้า / ร้านสินค้าเยอะ(Makro)สร้างหมวดภายในร้าน+แถบกรองได้ / แก้รูปได้ทุกจุด / **อัปโหลดรูปสินค้า-โลโก้: บีบ+แปลง WebP อัตโนมัติฝั่ง client ก่อนเก็บ**

**ตั้งค่า:** กิจการ/ร้านค้า+ค่าจำ/ผังบัญชี/รูปลายเซ็น/สถานะการเชื่อมต่อ(ไม่โชว์ key)

## หลังบ้าน (ซ่อนจากผู้ใช้)
ทุกรายการลงบัญชีคู่อัตโนมัติ ทุก line ติด book_scope (both/inhouse_only) → **งบ 2 ชุด:** ① งบส่วนตัว(รวมทุกอย่าง เห็นเงินจริง) ② งบจำลองถ้าจดนิติ(กรองเฉพาะเอกสารครบ + ตาราง VAT ซื้อ) — **งบ②ยังไม่สมบูรณ์: ต้นทุนขายจริงรอเชื่อม App_stock เฟสนี้เห็นแค่ค่าใช้จ่าย+เงินออก ให้แสดงหมายเหตุนี้** / ยอดย่อย(เอกสารครบ+ไม่ครบ) รวมกัน=ยอดรวมเสมอ

## ไฟล์และการจัดเก็บ
หลักฐานภาษี(บิล/สลิป): ต้นฉบับ JPEG 2560px→Google Drive (โฟลเดอร์ กิจการ/ปี/เดือน/CASE) + thumbnail WebP→Supabase / รูป master data(สินค้า/โลโก้): WebP เก็บ Supabase ได้เลย / sha256 กันซ้ำ / Drive ล่ม=คิว retry

## ลำดับงาน
1. ตรวจ tools → สร้างตาราง+RLS+seed(ผังบัญชี, ร้านตั้งต้น, sinค้าตั้งต้น) → schema.sql
2. Edge Functions (สมอง): ไฟล์/ไดรฟ์ → auth → master-data CRUD → คัดกรอง → จับคู่ → ลงบัญชี → เอกสาร → เซ็น → งบ
3. หน้าจอเส้นทางซื้อให้ใช้ได้ก่อน → หน้าอื่น → Dashboard → หน้า Data
4. SETUP.md (เชื่อม LINE/Google Drive/Claude API/SlipOK แบบจับมือทำ) + README แผนที่โปรเจกต์
ทำเท่าที่ระบุ (Phase 1) — ค่าเสื่อม/ปิดงบ/งบดุล/ภาษีเต็มรูป ยังไม่ทำหน้าจอ แต่เก็บข้อมูลดิบไว้ครบเพื่อต่อยอด
