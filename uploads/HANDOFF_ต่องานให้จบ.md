# ทำงานต่อให้จบ — KodKlean LIFF (ระบบการเงินฝั่งซื้อ)
งานนี้ทำมาเกือบเสร็จแล้ว เหลือขั้นสุดท้าย "ต่อสายให้ข้อมูลจริงวิ่ง + เอาขึ้นเว็บ" อ่านสถานะให้ครบก่อนลงมือ

## ⚠️ กติกาการทำงาน (สำคัญ — อ่านก่อน)
- **ทำทุกอย่างที่อยู่ในมือคุณให้จบในรอบเดียว ห้ามหยุดถามทีละขั้น** — ที่ผ่านมาหยุดถามหลายรอบจนเสียเวลา รอบนี้ให้ลงมือทำจนสุดทางที่ทำได้
- **ถามได้เฉพาะเรื่องที่ต้องใช้บัญชีส่วนตัวของเจ้าของเท่านั้น** (LINE, GitHub, Google) — นอกนั้นตัดสินใจเองแล้วทำเลย
- **ทุก function ที่เกี่ยวกับเงิน ต้องเทสต์ว่าเดบิต=เครดิตสมดุล แล้วรายงานตัวเลขจริง** ไม่ใช่แค่บอกว่าเสร็จ
- มี Supabase MCP tools (execute_sql, apply_migration, deploy_edge_function, list_tables, storage) — ใช้ได้เลย ตรวจ tool list ก่อนถ้าไม่แน่ใจ ห้ามบอกว่าทำไม่ได้ก่อนลอง

## สถานะปัจจุบัน (ทำเสร็จแล้ว — ห้ามสร้างใหม่ ใช้ของเดิมต่อ)
- **Backend เสร็จ:** Edge Functions `kk-finance` + `kk-finance-line` ครบทุก action
- **ฐานข้อมูลเสร็จ:** ตาราง `fin_*` + ผังบัญชี 39 บัญชี + seed 9 ร้าน + `ingredient_lot`→`ingredient_master` เชื่อมแล้ว
- **3 Edge Functions ทำงานจริง+เทสต์ผ่าน:** (1) บันทึกซื้อ→คัดกรอง route→ลงบัญชีคู่+แยก VAT 7%+สร้างใบสำคัญจ่าย/ใบรับรอง+flag ของถาวร (2) งบ 2 ชุด ส่วนตัว vs จำลองนิติ (3) เซ็นเอกสาร+เก็บ hash
- **UI/flow เสร็จ (สวย):** แต่ยังเป็น mockup — เก็บข้อมูลในเครื่องชั่วคราว ยังไม่ต่อ backend จริง
- **มี HANDOFF_PROMPT + GO_LIVE.md** ที่ล็อกรายละเอียดไว้ (อ่านประกอบ)

## ปัญหาที่ต้องแก้ (เกิดจากตอนทำ backend เลือกใช้ตารางเก่าที่รหัสคนละชุดกับ mockup)
mockup กับ backend ใช้รหัสร้าน/route คนละชุด ทำให้ต่อสายตรง ๆ ไม่ได้ — **นี่คืองานหลักที่ต้องเคลียร์ให้จบ ไม่ใช่ข้ออ้างให้หยุด**

## งานที่ต้องทำ (เรียงลำดับ ทำให้ครบทุกข้อ)

**1. แก้ data model ให้ 2 ฝั่งตรงกัน** — เลือกวิธีที่สะอาดสุด (แก้ backend ให้ตรง mockup / แก้ mockup ให้ตรง backend / ทำตัวแมปกลาง) ตัดสินใจเองแล้วทำเลย รายงานว่าเลือกวิธีไหน

**2. ต่อ front-end เข้า backend จริงทุกปุ่ม** — เปลี่ยนจากเก็บในเครื่อง (localStorage) เป็นอ่าน/เขียนผ่าน Supabase จริง ข้อมูลต้องไม่หายเมื่อปิดแอป/เปลี่ยนเครื่อง (localStorage ใช้ได้เฉพาะ draft ชั่วคราว) — ต่อตาม payload ใน HANDOFF

**3. redeploy Gemini (ตัวอ่านบิล) ให้เสร็จ** — ใช้ `supabase functions download kk-finance` ให้ได้ไฟล์ครบทุกไฟล์ (รอบก่อนดึงมา docs.ts ถูกตัดท้าย เห็นไม่ครบ) แล้ววาง ai.ts ทับ → deploy / เป็นฟีเจอร์เสริม ไม่มี key ก็ต้องไม่ error (ซ่อน/disable ปุ่มไว้)

**4. LINE auth ให้ทำงานจริง** — login ผ่าน LINE, ตรวจ token ฝั่ง server

**5. จัดโครงโฟลเดอร์ให้พร้อม deploy GitHub → Cloudflare Pages** — เสิร์ฟทั้งโฟลเดอร์ (รูปสินค้า/โลโก้อยู่ครบตาม path จาก data.js) + แยก env/secret ให้ถูกที่: ค่า public (Supabase URL/anon key, LIFF ID) → Cloudflare env / ค่าลับ (Gemini key, LINE token, Google service account) → Supabase Secrets ห้าม hardcode

**6. เขียน GO_LIVE.md ฉบับจับมือทำ** — ทุกขั้นที่เจ้าของต้องทำเอง (สร้าง LINE Login channel+LIFF, ตั้ง secret, push GitHub, ใส่ LIFF ID ใน config, เอา URL ใส่ LIFF Endpoint) แบบละเอียด กดตรงไหนบอกตรงนั้น

## กติกา UI (ตอนต่อของจริง)
รักษาหน้าตาการ์ดให้ใกล้ mockup มากที่สุด (เงา สี มุมโค้ง ตัวการ์ตูน) — ถ้าตรงไหนทำเหมือนเป๊ะไม่ได้ ให้บอกว่าต่างตรงไหน อย่าเงียบ ๆ ทำเรียบลงเอง / ตัวการ์ตูนอาเฮีย-แม่พันจับคู่วัยเดียวกัน ลายเส้นเดียวกัน / Mobile-first ปุ่มใหญ่ กดง่าย ไม่ใช่ตาราง Excel / ผู้ใช้ 100% Android
